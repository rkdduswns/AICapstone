# Client 가져온 문서 빠른 필터

작업일: 2026-11-16 (KST). 기준: `client_dev 7bb5115`, 확인한 `main 7e0991e`.
작업 브랜치: `feat/client-document-filter`.

## 목적·선행조건·범위

가져온 문서가 여러 개일 때 현재 받은 목록에서 원하는 파일을 빠르게 선택한다.
기존 문서 목록·실제 문서 ID 선택·원본 출처 메뉴·본문 찾기·업로드 결과 검증을 선행조건으로 사용한다.
실행 변경은 Client 문서 화면에 한정하며 서버 API·DB·Shared·수집·보호 정책·의존성을 변경하지 않는다.

## 구현 규칙

- 현재 `GET /documents?limit=20`으로 받은 **최근 최대 20건**에서만 찾는다.
  파일명·응답에서 확인한 원본 경로·연결 작업 ID를 대소문자 구분 없이 비교하고, 전체/PDF/DOCX 유형 조건과 함께 적용한다.
  응답에 없는 작업명이나 원본 경로를 추정하지 않는다. 전체 DB·문서 본문 검색은 이번 필터의 범위가 아니다.
- 원본 목록·서버 순서·실제 문서 ID는 바꾸지 않는다. 필터 편집과 해제에서 추가 조회·업로드·파일 접근을 하지 않는다.
- 선택 문서가 계속 보이면 본문·읽던 위치·텍스트 선택·본문 찾기 상태를 유지한다.
  선택 문서가 숨겨지면 첫 보이는 문서로 이동하고, 0건이면 선택·본문·찾기 위치·원본 메뉴를 함께 비운다.
  숨겨진 행이나 선택 해제 후 남은 Qt 현재 행 포인터를 원본 열기의 대상으로 쓰지 않는다.
- 새로고침 뒤에는 실제 문서 ID로 보이는 선택을 복원한다. 업로드 완료 문서가 필터 밖이면 완료 표시는 유지하고 숨김 안내를 추가한다.
  입력 필터를 자동으로 지우거나 숨은 문서를 강제 선택하지 않는다. 문서 가져오기의 연결 대상은 별도로 유지한다.
- 로딩·실패·403·재연결에서 필터 편집이 상태를 정상 빈 응답으로 바꾸지 않는다.
  필터는 실행 중 메모리에만 유지하며 새 저장 설정·검색 이력·본문 저장을 만들지 않는다.

## 검증·완료조건

1. 파일명·원본 경로·실제 연결 ID, 유형 AND, 한글·영문 대소문자와 원문/순서 보존.
2. 필터 안에 남은 선택의 본문·스크롤·찾기 유지, 숨은/해제 선택의 원본 동작 불가.
3. 필터 0건과 저장 문서 없음·조회 실패의 구분, 필터 해제에서 추가 요청 없음.
4. 갱신 순서 변경·업로드 완료·실패·쓰기 대기·재연결에서 실제 ID·현재 필터·명시적 업로드 대상 보존.
5. 기존 본문 찾기·원본 메뉴·Client 진단·실제 서버 HTTP·403·작은 화면·Windows EXE 회귀.
