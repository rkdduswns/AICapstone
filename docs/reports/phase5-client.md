## 구현 범위

- 어느 탭에서나 접근하는 일시정지/재개 버튼과 마지막으로 확인한 기록 가능 여부.
- 개인정보 보호 탭의 실행 파일 차단 목록 입력, 적용, 입력 되돌리기, 보호 상태 재확인.
- 설정과 기록 판정의 Shared 구조 및 [조회·개별 설정 변경 API](../dev/privacy-api.md).
- 정상 응답 확인 후에만 설정 적용 표시. PUT 결과가 요청값과 다르면 적용 미확인 처리.
- 일시정지와 차단 목록 요청 분리. 조회가 입력 초안을 덮어쓰지 않으며 일시정지가 초안을 함께 적용하지 않음.
- 입력 정규화/검증, 중복 요청 방지, timeout/오류/미구현 API 처리 및 늦은 응답 취소.
- PUT 자동 재전송 없이 GET으로 실제 설정 재확인. 통신 오류 시 이전 보호 판정을 미확인으로 전환.
- 공통 Qt 비동기 전송 계층에 JSON PUT 추가. Backend/의존성/저장소는 변경하지 않음.
- 메모리의 가상 설정으로 제어 화면을 확인하는 `tools/preview_phase5_client.py`.

기존 감지 상태와 저장 가능 여부를 구분해 표시한다. Client는 민감 문자열을 판정하거나 실제 작업 기록을 저장하지 않는다.

## 검증

Windows 10 / Python 3.14.7 / Qt 6.11.2의 기존 환경에서 확인했다.

| 범위 | 결과 |
|---|---|
| 신규 Client 가상 HTTP/계약 검증 | 36개 통과 |
| 기존 회귀 포함 전체 `pytest -q` | **186 passed**, 42.37초 |
| `ruff check src tests tools` | 통과 |
| `pip check` | 의존성 문제 없음 |
| Phase 5 미리보기 PNG | 한글, 상태/버튼, 탭, 목록 입력, 적용/되돌리기 배치 확인 |

신규 검증은 실제 Qt 이벤트 루프와 가상 HTTP 서버로 수행했다.
일시정지/재개 목표값과 전용 헤더, 적용 응답 확인, 입력 초안 보존, 목록 정규화/전체 해제,
잘못된 입력/응답/모순된 상태, 404/서버 오류/잘못된 JSON 복구,
서버 적용 후 응답 timeout에서 GET 재확인과 PUT 중복 방지, 재연결/종료 취소를 검사했다.
기존 현재 창 테스트의 가상 서버는 미구현 보호 API에 정상 404를 반환하도록 보완했다.

기존 Starlette/httpx deprecation warning 1건이 남아 있다.
신규 테스트 단독 실행의 제한 환경 캐시 경고는 전체 실행에서 발생하지 않았다.
GitHub Windows Python 3.11/3.12의 검증 결과는 이 브랜치 PR의 Actions 링크로 기록한다.

## 남은 실제 통합 검증

다음은 가상 상태 표시와 구분하며 아직 완료하지 않았다.

1. 일시정지 적용 즉시 진행 중 수집/저장도 중단되고 이후 기록이 저장되지 않음.
2. 차단 프로그램과 민감 문자열이 실제 저장소/후속 처리에 들어가지 않음.
3. 기록 재개 후 허용된 작업만 정상 저장됨.
4. 설정 변경으로 기존 기록이 변하지 않음.
5. 설정 지속 저장·재시작 정책, 동시 저장과 설정 변경의 순서, 로컬 API 접근 제어.

Backend 연결 후 위 항목을 검증하기 전까지 Phase 5 전체 완료 조건은 미충족이다.
개별 Phase 문서와 `00-progress.md`는 Client/Shared 및 가상 검증만 완료 표시했다.
