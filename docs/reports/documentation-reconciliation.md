## 현재 구현과 미완료 경계

현재 통합본에는 작은 검색창과 기존 관리 화면, 실제 HTTP·SQLite의 현재 작업/기록/보호 설정/복사 텍스트 조회,
선택 PDF·DOCX 업로드·추출, 실제 작업 ID 기반 웹·문서 연결과 저장 본문 조회가 있다.
문서·웹 본문의 HTTP 403을 저장 성공으로 처리하지 않는 Client 동작과, 확장 수집 중 잘린 본문의 전송 안내도 포함된다.

다음은 별도로 구분한다.

- `context_id`: 전달받은 새 계약과 현재 Backend의 `record_id` 계약이 다르다. 임의의 최근 작업 연결이나 확인하지 않은 필드 치환으로 완료 처리하지 않는다.
- `truncated`: 확장 전송·안내는 있지만 현재 Backend 요청 모델과 저장 경로에는 수집 잘림 정보의 보존이 없다. 저장 후 조회까지 같은 사실이 전달되는지는 후속 통합 대상이다.
- 설정 영속화·최근 기록 정렬 보정·검색 전처리/조각/색인: 별도 작업 브랜치가 있으며 [브랜치 기준](../dev/branch-integration.md)의 포함 여부를 따른다.
- 실제 조건/의미/혼합 검색, 검색 청크의 원본 역추적, 임베딩·LLM과 RAG HTTP 계약: 현재 일반 Client 실행에는 연결되지 않았다.
- 토큰 없는 Chrome 수집: 현재 확장은 수동 버튼과 연결 토큰을 사용한다. 후속 SQL/수집 설계를 현재 구현으로 설명하지 않는다.
- 메모·중요도·민감 본문 저장 동의: 합의·서버 계약이 확정됐다고 볼 근거가 없어 후순위로 유지한다.

## main 검토와 다음 검증

1. **병합 범위와 회귀 검증**: Client 묶음에 PR #16 Backend·확장·Shared 변경도 포함된다는 점을 검토한다. 프로젝트명 변경 후 패키지/서비스 식별자·실행 경로·문서 링크가 일치하는지와 자동 테스트 결과를 새 커밋 기준으로 기록한다.
2. **Backend 계약 정합**: 실제 저장된 작업 ID, 원래 파일 출처와 서버 사본 경로, 잘림 상태, 403 보호 거부와 기존 조회/설정 경로를 보존하는 통합 설계를 확정한다. 현재 검색 준비 상태를 실제 검색 서비스 성공으로 취급하지 않는다.
3. **실제 재검증**: Windows 10/11의 창 전환·복사·문서 경로, Chrome/Edge 설치·수동 캡처·403 안내, 배율·IME·다중 모니터·잘림 표시를 실제 환경에서 확인한다. 자동 테스트와 과거 EXE 실행 성공은 이 확인을 대체하지 않는다.
4. **후속 단계**: 자동 탭/파일 감지·URL 차단·재방문 합산·실제 검색/RAG는 각 Phase에서 구현과 검증을 진행한다. 메모·중요도·민감 본문 저장 동의는 신규 합의 전까지 보류한다.

실제 환경에서 아직 수행하지 않은 검증을 문서 수정이나 main 반영만으로 완료 표시하지 않는다.
