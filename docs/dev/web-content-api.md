# Phase 8 저장 웹 본문 조회 계약

상태: 2026-10-22 통합 브랜치에서 수동 확장 캡처→작업 ID 연결·저장→Client 본문 조회를 구현했다.
같은 출처의 중복 저장은 갱신한다. 본문 정제·자동 페이지 갱신·URL 차단 및 Windows 수동 검증은 남아 있다.
[확장 실행과 연결 계약](history-source-linking.md)을 따른다.
Client는 Backend에 저장된 본문만 읽으며 외부 URL에 접속하거나 DOM/HTML을 추출하지 않는다.

## 요청과 책임

- `GET http://127.0.0.1:<port>/records/web-content?record_id=<인코딩된 작업 ID>`.
- 요청 본문 없음, `Accept: application/json`. URL 주소를 요청 목적지나 별도 쿼리로 보내지 않는다.
- 기존 loopback 고정, 프록시 비활성화, 리다이렉트 거부, 3초 timeout을 사용한다.
- 작업 ID는 URL 쿼리 값으로 인코딩한다. `/`, `?`, `&`, `#`, `%`, 한글을 포함해도 같은 ID로 전달한다.
- 같은 기록에 여러 번 수집했다면 Backend는 현재 기록 출처에 연결된 최신 저장 본문 하나를 반환한다.
  수집 시점의 제목/URL/본문/시각은 하나의 일관된 스냅샷이어야 한다. 버전 목록/페이지 이동 이력은 이번 범위에 없다.
- 본문은 최근 기록 목록 응답에 포함하지 않는다. 사용자가 `웹 본문` 상세 탭을 열 때 별도 조회한다.
- `ContextRecord.browser` 및 URL 검증은 [Phase 7 브라우저 계약](browser-api.md)을 재사용한다.

## 성공 응답

HTTP 200 / `Content-Type: application/json`. 아래는 가상 데이터다.

```json
{
  "ok": true,
  "data": {
    "record_id": "sample-record",
    "content": {
      "page": {
        "browser": "chrome",
        "page_title": "가상 참고 자료",
        "url": "https://example.com/research?topic=sample#intro"
      },
      "captured_at": "2026-10-10T10:10:00+09:00",
      "text": "가상 웹페이지 본문입니다.\n줄바꿈을 유지합니다.",
      "truncated": false
    },
    "service": "contexttrace-backend",
    "api_version": 1
  },
  "error": null
}
```

| 필드 | 규칙 |
|---|---|
| `ok`, `error` | 필수 boolean true, 필수 null |
| `data.service`, `api_version` | 기존 서비스 이름, 정수 1. boolean/문자열 버전 거부 |
| `record_id` | 요청한 작업 ID와 정확히 일치 |
| `content` | 필수. 본문이 아직 없거나 추출 결과가 없으면 null, 본문이 있으면 객체 |
| `content.page` | 필수 BrowserPage. `chrome`/`edge`, 문자열 제목, 유효한 HTTP(S) URL. null URL 거부 |
| `content.captured_at` | 필수 시간대 포함 ISO 8601. [공통 시간 계약](activity-timing-api.md)을 사용 |
| `content.text` | 필수 문자열. 공백뿐인 본문 거부, 최대 50,000 Unicode 코드 포인트 |
| `content.truncated` | 필수 boolean. 길이 제한으로 전체의 일부만 저장했다면 true |

Client는 초과 본문을 임의로 잘라 정상 응답처럼 표시하지 않고 오류 처리한다.
`truncated: true`는 50,000자 이하에서도 허용한다. Backend 수집 제한/정제 결과에 따라 실제 길이가 더 짧을 수 있다.
빈 본문은 `content: null`로 표현하며 필드 생략이나 빈 문자열로 대체하지 않는다.
추가 필드는 무시하고 필수 필드가 잘못되면 응답 전체를 실패 처리한다.

## 출처 일치와 화면 동작

1. 최근 기록에 브라우저 출처와 HTTP(S) URL이 있는 경우에만 본문을 요청한다.
   일반 작업, 출처 없는 구형 기록, URL이 null인 내부/새 탭은 버튼을 잠그고 안내한다.
2. 작업 ID와 함께 응답의 브라우저 종류 및 URL이 현재 선택한 목록의 값과 정확히 같아야 한다.
   URL 원문은 최근 기록과 상세 응답에 일관되게 제공한다. Client가 임의로 다시 정규화해 동일 출처라고 판단하지 않는다.
3. 같은 ID에서 URL이 바뀌면 `페이지 출처가 변경되었습니다. 최근 기록을 새로고침해 주세요.`로 표시한다.
   목록을 갱신한 뒤 새 출처에 연결된 본문을 조회한다. 다른 URL의 내용을 이전 제목 아래 표시하지 않는다.
4. 페이지 제목은 같은 URL에서도 바뀔 수 있으므로 수집 당시의 제목을 표시한다. 빈 제목은 `(제목 없음)`이다.
5. 수집 시각은 Backend 값, 마지막 정상 조회 시각은 Client 수신 시각이다. UI에 구분해서 표시한다.
6. 본문은 읽기 전용 일반 텍스트다. HTML 태그, URL, 스크립트처럼 보이는 문자열을 실행하거나 외부 리소스를 로드하지 않는다.
7. 정상 본문은 글자 수, 제한된 본문은 `길이 제한으로 일부만 저장됨`, null은 `저장된 웹 본문이 없습니다`로 표시한다.
8. 성공한 상세를 다시 열 때 자동 재조회하지 않고 새로고침 버튼으로 갱신한다. 중복 조회 요청은 막는다.
9. 작업 선택/URL 변경, 목록 새로고침, 연결 재확인, 창 종료 시 이전 요청·출처·본문을 지운다.
   취소된 응답은 새 선택을 덮어쓰지 못하며 같은 ID의 URL 변경도 새 조회 대상으로 처리한다.

## 오류와 미지원

| 상황 | 동작 |
|---|---|
| HTTP 403 | 웹 본문 조회 거부 안내. 기존 출처/본문 제거 |
| HTTP 404 | 기능 미지원 또는 삭제된 기록 안내. 최근 기록 새로고침 유도 |
| 다른 HTTP 오류, 연결 실패, timeout | 각각의 오류 안내, 수동 재조회 허용 |
| JSON/필드/작업 ID 오류 | 호환되지 않는 응답 안내 |
| 브라우저 종류/URL 불일치 | 목록 출처 재확인 안내 |

이 오류들을 정상 빈 본문으로 처리하지 않는다. Client는 오류 본문이나 저장 텍스트를 파일/로그에 남기지 않는다.
구형 Backend의 최근 기록·기존 상세 API는 유지하고 새 경로 미지원만 별도로 안내한다.

## Browser/Backend 통합 조건

- Browser의 페이지 추출, UI 텍스트 제거, SPA 갱신 감지, 수집량 제한과 차단 페이지 수집 금지가 필요하다.
- Backend는 수신 데이터를 검증·정제하고 같은 페이지의 중복 본문을 제거해야 한다.
- 수집 시점의 URL/제목/시각/텍스트를 원본 작업 ID에 연결하고 페이지 전환 경쟁 상황을 처리해야 한다.
- 개인정보 검사는 저장 전에 수행한다. 길이를 자르는 처리가 민감정보 검사나 차단 규칙을 대신하지 않는다.
  Browser 차단만 신뢰하지 않고 Backend에서도 차단 URL·프로그램·일시정지·민감정보 조건을 적용한다.
- 저장/조회용 본문은 최대 50,000자로 제한하고 일부만 보관하면 `truncated`를 유지해야 한다.
  추출 방식과 영속 저장소 스키마는 이 조회용 dataclass로 강제하지 않는다.
- 정책상 본문 조회가 거부되면 HTTP 403으로 응답한다. Client는 URL 차단 목록만 보고 저장/조회 허용을 추측하지 않는다.
- 실제 기사/문서형 페이지, SPA 이동, 재방문, 긴 페이지, 차단 페이지 미수집·미저장은 연결 후 검증한다.
