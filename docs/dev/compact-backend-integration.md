# 소형 Client와 기존 Backend 연결 통합

## 목적과 기준

작은 검색창의 일반 실행에서 기존 실제 Backend 연결과 관리 기능을 함께 사용한다.
작업 확인일은 2026-11-13 (KST), 작업 브랜치는 `feat/compact-backend-integration`이다.
Client UI 기반은 `8947c21` (`feat/compact-client-usability`), 수집·이력 연결 기반은 `37c9b4a` (`fix/capture-truncation-privacy`, PR #16 후속)다.
이 문서는 해당 작업 시점의 통합 범위를 기록한다. 이후 Client 변경은 `client_dev`에 모았으며 실제 `main` 반영 여부는 [브랜치 통합 기준](branch-integration.md)을 따른다.
이 문서의 자동 검증 결과를 Phase 전체 완료나 실제 Windows 수동 검증 완료로 해석하지 않는다.

## 범위와 선행조건

- 일반 `python -m client [--port 포트]`는 작은 검색창에서 시작한다. 후속 Client의 메뉴 아이콘에서 최근 기록·문서 가져오기·개인정보 설정·현재 작업과 연결로 이동한다. 기존 관리 화면과 연결 객체를 이어 쓴다.
- 작은 창의 상태 버튼은 기존 관리 화면이 쓰는 연결·현재 작업·보호 상태를 사용한다. 관리 화면에 들어갔다 돌아와도 연결 객체와 검색 화면 상태를 유지한다.
- 기존 수동 문서 선택·업로드, 실제 작업 ID와 원래 Windows 파일 경로 연결, 저장 본문 상세 조회를 유지한다.
- 기존 브라우저 확장의 수동 캡처, 활성 작업 확인, HTTP 403 저장 거부 및 일부 본문 전송 안내를 유지한다.
- Backend가 실행돼 있어야 실제 연결을 확인할 수 있다. 브라우저 수동 수집은 현재 구현의 연결 토큰과 활성 Chrome/Edge 작업이 필요하다.

자연어 답변 API는 연결하지 않았다. 일반 검색 제출은 `답변 기능 준비 중`을 표시하며,
답변 요약·상세·정렬·복사 화면은 [가상 응답 미리보기](../../etc/compact-search-window.md#qt-미리보기-실행)로 확인한다.
메모·중요도·민감 본문 저장 동의는 별도 동작·계약 합의 범위다.

## 현재 실행과 확인 흐름

```powershell
python -m backend --port 8765
python -m client --port 8765
```

작은 창의 연결 상태 버튼 또는 `메뉴 아이콘 → 현재 작업·연결`에서 현재 작업 화면을 열고 `연결 확인`을 누른다.
현재 작업과 보호 상태가 모두 확인돼 허용된 경우 작은 창에 `기록 가능`을 표시한다.
이는 마지막으로 확인한 수집·보호 상태이며 개별 본문의 저장 성공 응답은 별도로 처리한다.

문서 연결은 `메뉴 아이콘 → 최근 기록 → 선택한 작업에 문서 연결`에서 시작한다.
대상 작업을 확인하고 문서를 선택한 뒤 최근 기록의 문서 본문을 조회한다.
브라우저 확장 설치·토큰 설정과 원래 출처 보존 규칙은 [이력·출처 연결 안내](history-source-linking.md)를 따른다.

## 최신 Backend 별도 브랜치와의 차이

2026-11-13 확인한 `feat/phase10-backend`의 `c95b440`은 검색 저장·임베딩 내부 구현을 포함하지만
현재 통합의 HTTP 경계와 다르다. 이번 통합은 해당 브랜치 전체를 병합하지 않는다.

| 경계 | 이번 통합의 기존 연결 | `c95b440`의 실제 코드 | 후속 확인 |
|---|---|---|---|
| 문서 업로드 | 선택 `record_id`와 원래 Windows `file_path`, 응답의 `activity_record_id`로 연결 확인 | 필수 multipart `context_id`, 서버 UUID 사본 경로 저장, 업로드 응답에 연결 ID·원래 경로 없음 | 작업 ID 필드 전환과 원래 출처·서버 사본 경로 구분 |
| 현재 작업 | 수집 중 실제 저장 작업의 문자열 `record_id` 반환 | 현재 작업 응답에 저장 작업 ID 없음 | 현재 브라우저 작업을 검증할 실제 ID 제공 |
| 브라우저 출처 | 확장이 실제 현재 작업 `record_id`를 보내고 응답의 최종 연결 ID 확인 | 요청 모델에 `context_id`·`record_id` 모두 없음 | 사용자 안내의 선택 `context_id` 계약을 API와 대조 |
| 웹 본문 | 확장이 `truncated`를 전송하고 잘림을 안내 | 요청 모델에 `truncated` 없음 | 수집 시 잘림을 저장·조회·청크까지 보존 |
| 민감 본문 | `/documents`와 `/browser/content`의 HTTP 403을 실패 처리 | 해당 경로에 민감 본문 검사·403 반환 없음 | 저장 이전 보호 검사와 Client 거부 표시의 실제 통합 |
| 최근 기록·상세 | 연결된 browser/document 출처와 작업별 저장 본문 조회 | 최근 기록에 출처 없음, 작업별 웹·문서 본문 및 개인정보 API 없음 | 기존 표시·보호·상세 조회 기능 유지 |
| 검색·답변 | 자연어 답변 준비 안내와 가상 화면 | 검색·임베딩 내부 모듈, 실제 검색·RAG HTTP 경로 없음 | 확정된 요청·응답 계약과 출처 검증 후 연결 |

사용자가 전달한 선택 `context_id`·선택 `truncated`·민감 본문 403 계약과
`c95b440`의 실제 API가 일치하지 않는다. 필드 이름만 바꾸거나 응답에 없는 출처·연결 ID를
만들어 성공 처리하지 않는다. 현재 작업 ID가 없을 때 임의의 최근 작업을 연결하지 않는다.
원래 파일 경로와 서버 보관 사본 경로는 서로 다른 의미로 다룬다.

## 검증과 완료조건

이번 통합의 검증은 가상 OS 입력과 실제 Uvicorn·QtNetwork·SQLite·DOCX 추출을 사용한다.
기존 [통합 테스트](../../tests/client/test_live_backend.py),
[출처 연결 테스트](../../tests/backend/test_history_sources.py),
[확장 전송 테스트](../../tests/browser/test_capture.mjs)를 함께 확인한다.
2026-11-13 Windows Python 3.14.7·Qt 오프스크린에서 전체 Python 테스트 **568 passed, 1 skipped**,
Node 확장 테스트 **11 passed**를 확인했다. Ruff·의존성 검사와 변경 안내 문서 6개의 로컬 링크 대상 검사도 통과했다.
새 통합 테스트 2개는 작은 창에서 실제 연결·기록 가능 상태 확인, 명시적인 작업 선택과 DOCX 업로드,
SQLite의 작업 ID·원래 경로·본문 조회, 검색어·작은 창 크기를 유지한 복귀를 검증한다.
일시정지 후 실제 HTTP 403에서 업로드·연결 성공 신호가 발생하지 않고 문서가 저장되지 않는 것도 확인했다.
일반 Client의 모듈 진입과 진단 실행의 연결 성공·실패 종료를 함께 검증했다.
Windows의 포트 충돌 오류 로그는 자식 출력과 테스트 읽기 인코딩을 UTF-8로 맞춰 확인했다.

완료조건:

- 일반 Client 진입에서 작은 창을 표시하고 메뉴 항목과 상태 버튼으로 같은 관리 화면을 연다.
- Backend 연결 후 현재 작업·보호 상태가 작은 창에 전달되고 관리 왕복으로 추가 조회 루프가 생기지 않는다.
- 선택한 실제 기록에 문서를 연결하고 원래 출처와 본문을 최근 기록에서 다시 확인한다.
- 웹 본문의 잘림·403 실패 처리를 유지하고 새 응답이 취소된 선택을 덮지 않는다.
- 일반 실행·진단 실행·기존 수집 및 Client 회귀 검증이 통과한다.

Windows 실제 Chrome/Edge 설치 동작, 창·탭 전환, 한글 입력기·화면 배율·여러 모니터,
자동 탭·파일 감지, URL 차단·설정 영속화·재방문 집계와 검색·LLM의 실제 통합은
이번 연결만으로 완료 처리하지 않는다. 기존 개별 Phase의 남은 검증을 따른다.
