# Phase 9 파일 출처 및 저장 문서 본문 조회 계약

상태: 2026-10-22 통합 브랜치에서 실제 PDF/DOCX 업로드·추출·저장과 명시적 작업 연결·본문 조회를 제공한다.
자동 열린 파일 식별과 Windows 수동 검증은 남아 있다. [문서 연결 절차](history-source-linking.md)를 따른다.
기존 [최근 기록 계약](recent-records-api.md)에 선택적 document를 추가한다.

## 파일 출처

ContextRecord.document는 생략/null이면 출처 없음이며 기존 기록을 계속 조회할 수 있다.
객체가 있으면 두 필드를 모두 제공한다.

~~~json
{"file_path": "C:\\가상 자료\\참고 문서.pdf", "file_type": "pdf"}
~~~

| 필드 | 규칙 |
|---|---|
| file_path | 문자열 Windows 절대 파일 경로. 드라이브 경로 및 UNC 공유 경로 허용 |
| file_type | 소문자 pdf 또는 docx. 경로 확장자는 대소문자 무시 후 유형과 일치 |

상대 경로, 드라이브 상대 경로, 웹/file URL, 제어 문자, 부모 이동(..), 장치 경로
(\\?\, \\.\), 경로 구성 요소의 < > : " | ? * 및 끝 공백/점은 거부한다.
Client는 PureWindowsPath로 문자열만 검사한다. 실제 파일 존재 여부, 접근 권한,
파일 이동/삭제, 파일 내용, UNC 서버 연결 여부를 자체 판단하지 않는다.
창 제목에서 경로를 추정하지 않는다. 사용자가 최근 기록에서 대상을 선택한 명시적 연결만 허용한다.
경로는 원문 그대로 유지하여 목록과 상세 응답에서 일관된 값으로 제공해야 한다.
추가 필드는 무시하며 출처 객체가 잘못되면 최근 기록 응답 전체를 실패 처리한다.

최근 기록 표의 파일 출처 열과 툴팁, 작업 정보 상세에 경로를 표시한다.
긴 경로는 가로 스크롤·툴팁·상세에서 전체 값을 확인한다.
파일 경로는 자동 실행하거나 HTML 링크로 해석하지 않는다.

## 본문 조회

- GET http://127.0.0.1:8765/records/document-content?record_id=sample-record
- 포트는 기존 실행 설정을 따른다. 작업 ID는 쿼리 값으로 인코딩한다.
- 파일 경로를 요청 목적지나 쿼리로 보내지 않는다. Backend가 기록 ID로 저장 본문을 찾는다.
- 요청 본문 없음, Accept: application/json, 고정 loopback, 프록시 비활성화,
  리다이렉트 거부, 3초 timeout은 공통 HTTP 계층을 따른다.
- 사용자가 문서 본문 상세 탭을 열 때만 요청한다. 최근 기록 응답에 본문을 넣지 않는다.
- 같은 작업의 현재 파일 출처와 연결된 최신 저장 본문 하나를 반환한다.

다음 가상 응답은 HTTP 200 / Content-Type: application/json이다.

~~~json
{
  "ok": true,
  "data": {
    "record_id": "sample-record",
    "content": {
      "document": {"file_path": "C:\\가상 자료\\참고 문서.pdf", "file_type": "pdf"},
      "captured_at": "2026-10-12T10:10:00+09:00",
      "text": "가상 문서의 첫 페이지입니다.\n두 번째 페이지입니다.",
      "truncated": false
    },
    "service": "contexttrace-backend",
    "api_version": 1
  },
  "error": null
}
~~~

| 필드 | 규칙 |
|---|---|
| ok, error | 필수 boolean true, 필수 null |
| data.service, api_version | 기존 서비스 이름과 정수 1. boolean/문자열 버전 거부 |
| record_id | 요청한 작업 ID와 정확히 일치 |
| content | 필수. 저장 본문이 없거나 추출 결과가 없으면 null, 있으면 객체 |
| content.document | 필수 출처 객체. 목록의 경로·유형과 정확히 일치 |
| content.captured_at | 시간대 포함 ISO 8601. Backend에서 본문을 추출한 시각 |
| content.text | 공백뿐인 문자열 거부, 최대 50,000 Unicode 코드 포인트 |
| content.truncated | 필수 boolean. 전체의 일부만 저장됐으면 true |

Client는 초과 본문을 잘라서 성공 표시하지 않고 오류 처리한다.
50,000자 이하라도 Backend의 추출/저장 제한에 따라 truncated: true를 허용한다.
필수 필드 누락과 빈 문자열은 정상 content: null로 처리하지 않는다.
텍스트는 읽기 전용 일반 텍스트로 표시하고 줄바꿈·태그 형태의 원문을 유지한다.
추출 시각과 Client의 마지막 정상 조회 시각은 별도로 표시한다.

## 출처와 비동기 상태

출처 없는 일반 작업·구형 기록은 문서 본문 요청을 생략한다.
응답의 작업 ID 및 파일 경로/유형을 선택한 목록과 대조한다.
같은 ID에서 출처가 바뀌면 최근 기록 새로고침을 안내하고 이전 본문을 지운다.
경로 대소문자/구분자를 Client가 임의 정규화하여 다른 값의 본문을 표시하지 않는다.
Backend가 목록과 상세에서 동일한 표현을 제공한다.

성공한 상세는 탭 재진입 시 자동 재조회하지 않는다. 버튼으로 수동 갱신한다.
선택 변경, 목록 새로고침, 재연결, 종료 시 요청·출처·본문을 함께 정리한다.
진행 중 중복 요청을 막고 취소된 응답이 새 선택을 덮지 않도록 한다.

| 상황 | Client 표시 |
|---|---|
| 정상 content: null | 저장된 문서 본문 없음 |
| HTTP 403 | 조회 거부, 개인정보 설정 확인 |
| HTTP 404 | 기능 미지원 또는 삭제된 기록, 목록 갱신 안내 |
| HTTP 410 | Backend가 출처 조회 불가를 확인, 이동·삭제 확인 및 목록 갱신 안내 |
| HTTP 500 등, 연결 실패, timeout | 각 오류 안내 및 수동 재조회 |
| JSON/필수 필드/작업 ID 오류 | 호환되지 않는 응답 |
| 파일 경로/유형 불일치 | 파일 출처 변경, 목록 갱신 안내 |

오류는 정상 빈 결과와 구분한다. 오류 본문이나 문서 내용을 로그/파일에 남기지 않는다.
원본 파일이 이동/삭제돼도 유효한 저장 본문과 과거 출처를 유지할 수 있다면 HTTP 200으로 조회할 수 있다.
410은 실제 파일의 현재 존재 여부를 Client가 검사했다는 뜻이 아니다.

## Backend 연결 시 남은 검증

실제 파일 식별, 지원 유형 판별, PDF 여러 페이지/DOCX 추출, 빈/이미지 전용 문서,
이동·삭제, 재열람·중복 처리, 원본 작업 ID·열람 시각 연결을 구현한다.
개인정보 검사는 저장 전에 적용하며 차단 프로그램·일시정지·민감 텍스트를 확인한다.
이 dataclass는 추출 라이브러리·영속 저장 스키마·검색 분할 방식을 강제하지 않는다.
