# 검색 중심 소형 창 설계

## 목적과 기준

앱을 켜 두는 동안 검색창에 집중할 수 있게 하고, 검색 후에는 짧은 답변을 먼저 보여준다. 전체 답변과 근거는 필요할 때 같은 창에서 펼친다. 첫 검색 전에도 `결과 보기`로 결과 영역을 열 수 있다.

일반 실행은 [ApplicationWindow](../src/client/application_window.py)의 작은 검색창에서 시작한다. `관리` 메뉴로 같은 창에서 기존 [MainWindow](../src/client/window.py)의 현재 작업·최근 기록·개인정보 보호·조건 검색 탭에 접근한다. [Phase 12 미리보기](phases/phase012.md#client-미리보기-실행)는 가상 웹·PDF 조각을 표시하는 별도 실행 도구다. 이 설계는 Phase 13의 답변·근거 UI와 Phase 14의 검색 흐름을 다룬다. 실제 검색·LLM API 연결은 후속 범위다.

2026-11-13 `feat/compact-backend-integration`에서는 기존 `fix/capture-truncation-privacy`의 서버 통합과 문서 가져오기를 소형 창의 관리 화면에 합쳤다. [통합 범위와 Backend 계약 비교](../docs/dev/compact-backend-integration.md)를 따른다.

## 일반 Client 실행

```powershell
python -m client
python -m client --port 8765
```

기본 상태는 440×112 논리 픽셀이다. 관리 화면에서 `연결 확인`을 누르면 지정한 포트의 기존 Backend 연결을 확인한다. 자연어 질문 제출은 답변 API 연결 전까지 `답변 기능 준비 중` 안내를 표시한다. 가상 답변은 아래 미리보기 도구에서 확인한다.

작은 창의 연결·기록 상태 버튼은 같은 관리 화면의 현재 작업·연결 설정을 연다. 기존 연결과 현재 작업·개인정보 상태 신호를 사용해 처음에는 `연결 미확인`, 재확인 중에는 진행 상태를 표시한다. 연결 실패나 상태 채널 수신 실패, 확인 대기, 설정 변경 중 상태를 각각 반영하고, 일시정지와 프로그램·URL·민감정보 차단 사유도 표시한다. 현재 작업의 수집 상태와 보호 정책의 허용 상태가 모두 확인되면 `연결됨 · 기록 가능`을 표시한다.

## 화면 상태

크기는 창 테두리를 뺀 Client 영역의 목표 논리 픽셀이다. 기본 440×112는 현재 620×740 창 면적의 약 11%다.

| 상태 | 목표 크기 | 표시 내용 |
|---|---|---|
| 기본 | 440×112 | 검색 입력, `검색`, `결과 보기`, `관리` |
| 검색 전 결과 영역 | 440×168 | 기본 영역과 `아직 검색 결과가 없습니다` 안내 |
| 검색 중 | 440×112 | 기본 영역과 짧은 진행 상태 |
| 답변 요약 | 440×최대 248 | 검색 입력, 짧은 답변, `전체 답변·근거`, `결과 숨기기`. 짧은 요약의 높이에 맞춰 줄인다. |
| 답변 상세 | 560×496 | 검색 입력, 전체 답변, 근거 목록과 선택한 근거, `상세 접기`, `결과 숨기기` |
| 결과 없음·근거 부족·오류 | 기본 크기 기준 | 상태별 안내 한 줄. 검증된 근거가 있는 경우 `근거 보기` 제공 |

검색 입력은 모든 검색 상태에서 위에 둔다. 요약은 공급자가 준 짧은 답변에서 요지를 먼저 읽을 수 있게 하고, 문단과 핵심 항목의 구분을 살려 표시한다. 검색 결과 목록과 개별 조각은 상세의 근거 영역에 둔다. 요약이 따로 없는 응답은 전체 답변 앞부분을 `답변 미리보기`로 표시한다.

요약은 현재 표시 너비와 Qt 글꼴로 줄바꿈을 계산해 최대 5개 표시 줄·200자·110 논리 픽셀 높이 안에 둔다. 요약이 잘리면 `일부 표시 중`을 표시한다. 수신한 전체 답변과 근거는 메모리에 유지하여 상세에서 확인할 수 있다.

## 전환과 조작

- 앱을 시작하면 기본 상태에서 검색 입력에 초점을 둔다. `결과 보기`는 검색 전에도 활성화한다. 결과가 없는 상태에서 열면 빈 안내만 표시하며 요청은 사용자 제출로 시작한다.
- `검색`이나 Enter로 현재 입력을 제출하면 기존 결과를 비우고 작은 창에서 진행 상태를 표시한다. 검색 문장이나 조건을 수정하면 이전 요청과 결과를 정리하고 기본 크기로 돌아간다. 새 응답은 현재 요청의 식별자와 일치할 때만 반영한다.
- 성공 응답이 현재 요청과 일치하면 요약을 연다. 기다리는 중 사용자가 결과 영역을 직접 닫았다면 기본 크기를 유지하고 `결과 보기`로 응답을 다시 열 수 있게 한다.
- `전체 답변·근거`를 누르면 받은 응답을 재사용해 같은 창의 상세를 연다. `상세 접기`는 요약으로 돌아가고 `결과 숨기기`는 기본 상태로 돌아간다. 숨긴 뒤 입력을 수정하기 전까지 현재 결과를 메모리에 유지하며, `결과 보기`를 누르면 요약으로 다시 연다.
- 결과 없음, 근거 부족, 통신 오류는 별도 상태로 표시한다. 근거 부족은 답변 대신 상태를 표시하고, 검증된 출처가 제공됐다면 사용자가 근거를 직접 펼칠 수 있게 한다. 오류 시 같은 입력으로 수동 재시도를 제공한다.
- Esc는 상세에서 요약으로, 요약이나 열린 빈 패널에서 기본으로 돌아간다. 닫을 때는 열기 버튼으로 초점을 돌려준다. 기본 창에서 검색을 기다리는 중에는 `취소`나 Esc로 중단할 수 있다. 한글 입력기 조합 중 Enter는 입력 조합을 우선한다.
- `관리`에서 기존 현재 작업·최근 기록·개인정보 보호·조건 검색과 해당 빌드의 문서 가져오기에 접근한다. `검색으로 돌아가기`나 관리 화면에서 Esc를 누르면 검색 입력·현재 결과·근거 정렬 상태와 화면 크기를 복원한다. 관리 화면과 연결 객체는 다시 사용한다.

## 전체 답변과 근거

상세의 읽기 순서는 전체 답변 → 인용된 근거 → 선택한 근거의 본문과 출처다. 근거별 제목, 관련 본문, 확보 당시 URL 또는 파일 경로를 보존하고 열람 시각과 본문 확보 시각을 구분한다. 출처 형식과 작업 ID 검증에는 기존 검색 조각 계약을 사용한다. [검색 조각·출처 계약](../docs/dev/search-data-contract.md)

`답변 처음으로`는 상세의 첫 부분으로 스크롤을 돌린다. `답변 복사`는 수신한 전체 답변 원문을, `출처 복사`는 선택한 근거의 원래 URL 또는 파일 경로를 클립보드에 넣는다. 복사 결과는 상세 안에 안내한다.

근거가 둘 이상이면 상세의 정렬 메뉴에서 관련도, 최근·오래된 열람, 본문 긴·짧은 순을 선택할 수 있다. 관련도는 공급자가 반환한 순서다. 현재 계약에는 정확도 점수 필드가 없다. 열람순은 마지막 활성 시각을 시간대까지 반영해 비교하고, 본문 길이순은 수신한 조각의 글자 수를 기준으로 한다. 값이 같으면 원래 순서를 유지한다.

정렬은 현재 응답의 표시 순서에만 적용한다. 답변의 인용 번호와 선택한 근거는 정렬 전과 동일하다.

답변에서 참조한 근거 번호는 검증된 출처 목록과 대응할 때만 이동에 사용한다. 답변·조각·출처는 일반 텍스트로 렌더링하고, 세로 공간이 부족하면 상세 본문만 스크롤한다. 검색 입력과 닫기 동작은 계속 보이게 한다.

## 창 크기와 구현 경계

- 창 전환은 현재 위치의 좌상단을 기준으로 한다. Qt의 `sizeHint`로 실제 글꼴·여백을 반영하고 활성 화면의 `availableGeometry` 안에 맞춘다. Windows 화면 배율과 여러 모니터에서도 접기 버튼에 접근할 수 있어야 한다.
- 접힌 결과 영역과 기존 탭은 기본 창의 최소 높이 계산에서 제외한다. 요약과 안내는 표시 높이를 제한하고, 자세한 내용은 상세에서 읽는다. 표시 모드는 한 창 안에서 전환한다.
- 화면 모델은 현재 요청의 식별자와 입력, 응답 상태, 짧은 답변, 전체 답변, 검증된 근거를 표현한다. 이 항목은 UI와 가상 공급자 사이의 경계이며 실제 요청·응답 필드는 Backend 계약 합의 시 정한다.
- 일반 앱은 같은 관리 화면의 연결 상태와 수집 조회를 재사용한다. 창 모드 전환마다 별도 조회 루프를 만들지 않는다. 검색·답변 제공과 Chrome 수집·SQL 저장은 각각 기존 책임 경계를 따른다.
- 관리 화면이 작업 영역보다 길면 내용만 스크롤하고 검색 복귀 버튼은 상단에 둔다.

## Qt 미리보기 실행

```powershell
python tools/preview_compact_search.py
```

검색어를 입력하고 Enter를 누르면 고정 가상 응답을 받는다. `--state empty`, `--state insufficient`, `--state error`로 상태별 안내를 확인할 수 있다. `--view compact|summary|detail`과 `--snapshot PATH`를 함께 지정하면 원하는 화면을 PNG로 저장한다.

미리보기는 Phase 12의 출처 표시와 가상 근거를 재사용한다. 입력·결과 접기·응답 취소를 같은 창에서 확인할 수 있고, 긴 URL과 본문은 상세 한 곳에서 줄바꿈하여 스크롤한다.

Windows Python 3.14.7의 Qt 오프스크린에서 정렬 테스트 2개를 포함해 Client 테스트 461개가 통과했고 POSIX 전용 1개를 건너뛰었다. 시간대, 동률, 조각 글자 수, 인용 번호와 선택 유지, 추가 요청이 없는 동작을 확인했다. 소형 창 구현 시 Qt 배율 150%에서 화면 경계와 긴 답변 스크롤을 검증했다. Ruff와 의존성 검사도 통과했다.

2026-11-08 일반 실행 연결에서 Client 회귀 테스트 465개가 통과했고 1개를 건너뛰었다. 관리 스크롤 보완 뒤에는 작은 작업 영역을 포함한 통합 테스트 5개와 기존 소형 창 테스트 9개를 확인했다. 실제 Client 모듈 진입에서 포트 전달과 관리 탭 복귀를 확인했고, Qt 배율 150%의 533×533 작업 영역에서도 관리 화면이 화면 안에 배치됐다.

2026-11-13 연결·기록 상태와 요약 잘림 안내, 답변·출처 복사를 보완한 뒤 Windows Python 3.14.7의 Qt 오프스크린에서 Client 테스트 477개가 통과했고 POSIX 전용 1개를 건너뛰었다. 상태 채널별 실패와 복구, 기록 차단·설정 변경 상태, 실제 표시 폭과 한글·긴 문자열·이모지의 줄 높이, 전체 답변과 정렬 후 선택 출처의 원문 복사, 답변 처음으로 이동을 확인했다. 요약·상세 PNG를 확인했고 Ruff와 의존성 검사도 통과했다. 답변 조작은 가상 응답으로 검증했다.

## 남은 검증과 연결

Windows의 실제 화면 배율과 여러 모니터에서 창 위치, 한글 입력기, 키보드 초점과 상세 스크롤을 확인한다. 실제 답변은 Backend와 합의한 요청·응답 계약으로 연결한다. 메모·우선순위·보호 저장은 동작과 데이터 계약 합의 후 진행한다.
