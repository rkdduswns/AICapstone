# Client 최근 기록 날짜별 보기

작업일: 2026-11-14 (KST). 기준: `client_dev 636fd40`, 확인한 `main 7e0991e`.
작업 브랜치: `feat/client-recent-timeline`.

## 목적·선행조건

현재 받은 기록을 날짜와 시각으로 읽고, 선택한 실제 작업의 출처·본문·문서 연결로 이어간다.
Phase 14의 Client 작업 타임라인을 준비하는 작은 읽기 전용 단계다.
기존 `/records/recent?limit=20`, 검증된 `ContextRecord`와 최근 기록 상세·빠른 필터를 선행조건으로 사용한다.

## 범위와 경계

- 기존 최근 기록 화면 안에서 목록과 날짜별 보기를 전환한다. 별도 상시 수집기·서버 API·저장소를 추가하지 않는다.
- **현재 받은 최근 20건**만 다룬다. 각 기록의 `last_active_at`을 PC 현지 시각으로 변환하여 날짜별로 표시한다.
  시작 시각이나 본문 수집 시각으로 대체하지 않으며 같은 시각 기록의 기존 순서를 유지한다.
- 날짜 머리글의 개수는 현재 목록·필터 안의 개수다. 그날의 전체 기록 수나 하루 전체 이력을 뜻하지 않는다.
- 각 항목은 실제 작업 ID로 기존 선택과 연결한다. 제목·날짜·프로그램·파일 경로로 다른 작업을 추정하지 않는다.
  날짜 머리글·빈 결과·숨겨진 항목·선택 해제 상태는 문서 연결 대상이 될 수 없다. Qt의 현재 행 포인터가 남아도 실제 선택이 없으면 보기 전환으로 다시 선택하지 않는다.
- 두 보기는 같은 필터·선택·상세를 사용한다. 보기 전환으로 새 목록 요청을 만들지 않으며 선택한 기록의 기존 본문 조회는 유지한다.
- Client 실행 코드만 변경한다. Backend·DB·Shared·브라우저 확장·요청 및 응답 필드·의존성은 그대로 둔다.
  선택 보기·날짜·작업 목록·필터·본문·출처를 새로 영속 저장하지 않는다.

서버의 세션 구성·세션 시작/종료·완전한 작업 구간·하루 총 활성 시간·전체 날짜 범위 검색·삭제 기능은 이번 범위가 아니다.
현재 날짜별 보기를 실제 세션 타임라인 완료나 Phase 14 전체 완료로 처리하지 않는다.

## 구현·검증·완료조건

검증할 항목은 다음과 같다.

1. 서로 다른 시간대·자정 경계·동일 시각 기록의 현지 날짜와 기존 표시 순서.
2. 보기 전환 시 추가 목록 요청 없음, 실제 ID 기반 선택·필터·상세 유지.
3. 날짜 머리글·필터로 숨긴 항목·빈 결과의 연결 금지.
4. 새로고침·조회 실패·재연결 시 양쪽 보기와 상세 함께 초기화, 같은 실제 ID 선택 복원.
5. 작은 화면·긴 제목·키보드 이동과 기존 문서/웹 본문·403·연결 동작 회귀.
