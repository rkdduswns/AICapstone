# 핵심 기능

ContextTrace의 핵심 기능은 **수집 → 보호 → 저장 → 검색 → 근거 제시**의 흐름으로 구성됩니다.

---

## 1. Windows 작업 맥락 자동 수집

백그라운드에서 현재 활성화된 창을 주기적으로 감지하고 작업 정보를 기록합니다.

### 수집 대상

| 항목 | 설명 |
|---|---|
| 프로그램 | Chrome, Edge, Acrobat Reader, Word, VS Code 등 |
| 프로세스 | `chrome.exe`, `WINWORD.EXE` 등 |
| 창 제목 | 웹페이지 제목, 문서명, 파일명 |
| URL | Chrome / Edge의 현재 페이지 주소 |
| 파일 경로 | 로컬 문서 경로 |
| 클립보드 텍스트 | 사용자가 복사한 텍스트 |
| 활성 시간 | 해당 창을 실제로 보고 있었던 시간 |
| 시각 | 작업이 발생한 시간 |

### 수집 흐름

```text
현재 활성 창 감지
      ↓
프로세스 식별
      ↓
창 제목 추출
      ↓
URL / 파일 정보 수집
      ↓
개인정보 보호 필터
      ↓
저장
```

---

## 2. 프로그램별 수집 어댑터

프로그램마다 정보를 얻는 방식이 다르기 때문에 하나의 수집 방식으로 처리하지 않고 어댑터 구조를 사용합니다.

```text
작업 맥락 수집기

├── 창 정보 어댑터
├── 브라우저 어댑터
├── 파일 어댑터
├── 클립보드 어댑터
└── 프로그램별 확장 어댑터
```

### 창 정보 어댑터

현재 가장 앞에 떠 있는 Windows 창의 정보를 수집합니다.

주요 정보:

```text
프로세스
프로그램명
창 제목
활성 시작 시각
활성 종료 시각
활성 시간
```

### 브라우저 어댑터

Chrome 또는 Edge에서 보고 있는 웹페이지 정보를 수집합니다.

주요 정보:

```text
페이지 제목
URL
도메인
열람 시각
```

브라우저 URL은 Windows API만으로 안정적으로 확보하기 어렵기 때문에 초기 버전에서는 **브라우저 확장 프로그램을 보조 수집 모듈**로 사용합니다.

```text
Chrome / Edge
      ↓
브라우저 확장 프로그램
      ↓
로컬 통신
      ↓
ContextTrace
```

### 파일 어댑터

현재 열려 있는 문서와 관련된 정보를 수집합니다.

지원 대상 예시:

- PDF
- DOCX
- TXT
- 소스 코드 파일

수집 정보:

```text
파일명
파일 경로
확장자
사용 프로그램
열람 시각
```

### 클립보드 어댑터

사용자가 복사한 텍스트는 현재 관심 있는 정보일 가능성이 높기 때문에 중요한 작업 맥락 신호로 활용합니다.

```text
복사 텍스트
복사 시각
출처 프로그램
출처 창
```

민감 정보가 포함될 수 있으므로 반드시 개인정보 보호 필터를 거친 후 저장합니다.

## 3. 활성 시간 추적

단순히 창을 열었다는 사실만 저장하지 않고, 실제로 해당 자료를 얼마나 오래 확인했는지 기록합니다.

예시:

```text
Chrome - SaaS Metrics Report

13:21:00 ~ 13:26:32
활성 시간: 332초
```

저장 항목:

```text
opened_at
last_active_at
active_duration
foreground_count
```

활성 시간과 재방문 횟수는 검색 결과의 우선순위를 조정하는 데 사용할 수 있습니다.

---

## 4. 작업 맥락 전처리

수집된 로그를 그대로 저장하지 않고 검색에 적합한 형태로 정리합니다.

```text
원시 작업 로그
      ↓
중복 제거
      ↓
텍스트 정제
      ↓
문서 분할
      ↓
작업 세션 구성
      ↓
임베딩 생성
      ↓
색인
```

### 중복 로그 병합

동일한 창을 일정 시간 보고 있으면 비슷한 기록이 반복적으로 발생합니다.

```text
13:20 SaaS Report
13:20 SaaS Report
13:21 SaaS Report
13:21 SaaS Report
```

이를 하나의 기록으로 병합합니다.

```text
SaaS Report
13:20 ~ 13:21
활성 시간: 92초
```

### 긴 문서 분할

PDF나 문서 전체를 하나의 검색 단위로 저장하지 않고 적절한 크기의 텍스트 조각으로 나눕니다.

```text
문서
 ↓
문서 조각 1
문서 조각 2
문서 조각 3
문서 조각 4
```

각 문서 조각은 반드시 원본 작업 기록과 연결합니다.

## 5. 의미 기반 검색

사용자가 파일명이나 URL을 정확히 기억하지 못해도 내용의 의미를 기반으로 검색합니다.

예:

> 고객 유지율이 SaaS 성장에 중요하다고 설명했던 자료가 뭐였지?

텍스트 임베딩을 활용해 의미적으로 가까운 기록을 찾습니다.

---

## 6. 조건 기반 + 의미 기반 혼합 검색

사용자의 질의에는 의미뿐 아니라 시간, 프로그램, 파일 형식 등의 조건이 함께 들어갈 수 있습니다.

예:

> 지난주에 Chrome에서 읽었던 B2B SaaS 수익 모델 관련 자료 찾아줘.

질의 분석:

```text
지난주
→ 시간 조건

Chrome
→ 프로그램 조건

B2B SaaS 수익 모델
→ 의미 검색
```

검색 흐름:

```text
사용자 질의
      ↓
질의 분석
      ↓
시간 / 프로그램 / 파일 조건 추출
      ↓
후보 로그 필터링
      ↓
의미 기반 벡터 검색
      ↓
검색 결과 재정렬
```

---

## 7. 검색 결과 우선순위 계산

검색 결과는 의미 유사도만으로 정렬하지 않습니다.

활용 가능한 요소:

```text
의미 유사도
최근 열람 여부
활성 시간
재방문 횟수
조건 일치 정도
```

개념적으로 다음과 같은 형태의 점수를 사용할 수 있습니다.

```text
검색 점수
=
의미 유사도
+ 최근성
+ 활성 시간
+ 재방문 빈도
+ 메타데이터 일치도
```

## 8. 근거 기반 RAG

검색된 작업 기록을 기반으로 LLM이 답변을 생성합니다.

```text
사용자 질문
      ↓
혼합 검색
      ↓
관련 작업 기록
      ↓
LLM
      ↓
답변 + 출처
```

응답에는 가능한 경우 다음 정보를 포함합니다.

```text
문서명
URL 또는 파일 경로
열람 시각
사용 프로그램
관련 내용
```

예시:

```text
지난주 B2B SaaS 관련해서 확인한 자료 중
관련성이 높은 자료는 다음과 같습니다.

문서:
SaaS Metrics Report

출처:
https://example.com/saas-report

열람 시간:
2026-09-10 14:22 ~ 14:27

사용 프로그램:
Google Chrome

관련 내용:
NRR과 CAC Payback Period를 SaaS 성장 지표로 설명한 부분을 확인했습니다.
```

---

## 9. 근거 부족 시 답변 제한

충분한 검색 결과가 없을 경우 LLM이 임의로 답을 만들어내지 않도록 합니다.

```text
검색 점수 확인
      ↓
기준 이상
→ RAG 답변 생성

기준 미만
→ 충분한 기록이 없음을 안내
```

예시:

> 해당 내용을 열람했다는 충분한 기록을 찾지 못했습니다.

---

## 10. 작업 세션 자동 구성

시간적으로 가깝게 발생한 여러 작업 기록을 하나의 작업 단위로 묶습니다.

예:

```text
Chrome
OpenAI Agents

↓ 2분

PDF
Agent Survey.pdf

↓ 7분

VS Code
rag.py

↓ 3분

Chrome
LangGraph Documentation
```

이를 다음과 같은 하나의 작업 세션으로 구성할 수 있습니다.

```text
세션: AI Agent 구현 조사
시간: 13:10 ~ 14:02

참고 자료
- OpenAI Agents
- Agent Survey.pdf
- LangGraph Documentation

사용 프로그램
- Chrome
- Acrobat Reader
- VS Code
```
