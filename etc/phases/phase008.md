# Phase 8 - 웹페이지 본문 수집

## 2026-10-22 통합 상태

수동 캡처 확장에서 보낸 본문을 원본 작업 FK에 연결하고 기존 Client 상세 조회 API를 구현했다.
같은 출처 재전송은 본문을 갱신하며 출처/작업이 바뀐 늦은 본문은 거부한다. 가상 OS 입력과 실제 HTTP·SQLite·Qt로 검증했다.
실제 Chrome/Edge 설치·기사/SPA 수동 검증, 본문 정제, 자동 갱신·URL 차단은 남아 있다.
브랜치: `feat/client-backend-integration`. [통합 검증](../../docs/reports/client-backend-integration.md).
아래 기존 날짜의 범위 설명은 최초 Client 선행 개발 시점의 기록이다. 전체 Phase는 IN_PROGRESS다.

## 목표
URL과 제목뿐 아니라 사용자가 실제로 본 웹페이지의 검색 가능한 텍스트를 확보한다.

## 진행 상태와 범위

- 2026-10-10: **Client DONE / 전체 IN_PROGRESS**, `feat/phase8-client`.
- Client 선행 개발을 위해 저장 웹 본문 확인 화면과 조회 계약을 추가한다.
- 선행조건: Phase 4 최근 기록, Phase 7 브라우저 출처. 미병합 `feat/phase7-client`에서 분기했다.
- 이번 범위: 본문·출처·수집 시각 표시, 상태/오류 처리, Shared 계약 및 가상 HTTP 검증.
- Client 완료 근거: 전체 297개 테스트, 정적 검사·의존성 검사·가상 화면 확인.
- Browser/Backend 실제 본문 수집·정제·중복 제거·저장 및 차단 검증은 남아 있다.
