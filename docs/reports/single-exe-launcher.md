# 강써치 단일 EXE 실행·종료 통합

작업일: 2026-11-16 (KST). 기준: `client_dev 84588b4`, 확인한 `main 7e0991e`.
작업 브랜치: `feat/single-exe-launcher`.

## 목적·선행조건·범위

사용자가 Client·Backend를 각각 실행하던 Windows 배포를 `강써치.exe` 실행 한 번으로 바꾼다.
기존 Client HTTP·Backend lifespan·보호 설정/DB·Windows 패키징과 읽기 진단을 재사용한다.
새 `desktop` 패키지는 실행 조합과 프로세스 수명만 담당하며 Client가 Backend 내부를 import하지 않는다.
Backend API·DB 스키마·보호 정책·브라우저 확장·기존 저장 경로·의존성은 변경하지 않는다.

## 실행·소유 규칙

- 배포에는 실제 EXE가 하나만 있다. UI와 worker는 같은 EXE의 역할로 분리하여 기존 HTTP 경계를 유지한다.
- 창을 먼저 표시하고 로컬 서버를 비동기로 확인한다. 비어 있는 포트에서는 소유 worker를 숨김 실행한다.
  worker는 포트를 독점 확보한 뒤에만 DB를 열고, 자기 서버의 준비 이벤트와 검증된 health가 모두 확인된 경우에만 연결한다.
  Windows에서 연결 거부가 늦어져 초기 확인이 시간 초과되어도 포트 확보 단계에서 안전하게 판단한다.
- 같은 사용자·포트의 UI 중복 실행은 잠금으로 막는다. 이미 실행 중인 호환 외부 서버는 재사용하지만 종료 권한을 갖지 않는다.
  `--db-path`를 명시한 경우 기존 서버의 DB 동일성을 API로 확인할 수 없으므로 조용히 재사용하지 않는다.
- 정상 종료는 소유 채널로 Uvicorn 종료를 요청하여 기존 lifespan의 마지막 작업 정리를 수행한다.
  GUI가 충돌하면 열린 부모 프로세스 핸들을 감시하는 worker가 자신만 종료한다. 다른 서버 PID를 추정하여 종료하지 않는다.
  응답 없는 소유 프로세스의 강제 정리는 본인 프로세스 트리로 제한한다.
- worker 역할은 GUI import 전에 분기하고 windowed 런타임의 표준 출력 부재도 처리한다.
  기본 포트·브라우저 토큰·`.contexttrace/activity.db`·저장된 보호 설정을 유지하고 임의 포트나 새 DB로 우회하지 않는다.

## 구현·검증·완료조건

1. 기존 `python -m client`, `python -m backend`와 진단 JSON 호환, 통합 `python -m desktop` 역할 분기.
2. 자동 시작·정상 종료·같은 DB/포트 재시작과 보호 설정 복원.
3. 기존 서버 재사용/보존, 명시 DB 충돌·다른 서비스 점유 시 DB 미생성 및 안전한 실패.
4. 중복 창 차단, 부모 강제 종료 뒤 worker·포트 정리, 시작 중 취소·시간 초과·소유 준비 검증.
5. 네이티브 단일 EXE의 숨김 worker·문서 처리·403·읽기 진단과 ZIP/해시/소스 대조.

완료조건은 위 동작과 기존 Client 회귀 통과 및 최종 Windows 단일 EXE 실행 확인이다.

- Windows Python 3.14.7·Qt 오프스크린에서 역할 분기·worker/GUI 수명·실제 Client/Backend HTTP·기존 연결/진단과 패키징 검사를 포함한 관련 검증 **133개 통과**를 확인했다.
- worker의 실제 Windows 제어 검증 **12개**는 정상 종료·설정 복원·같은 포트 재시작·포트 충돌 전 DB 미생성·부모 충돌 정리·PID 경계를 확인한다.
- UI 소유 수명 단위 검증 **18개**, 실제 통합 앱 프로세스 검증 **5개**에서 외부 서버 보존·명시 DB 거부·포트 충돌·중복 창과 실제 GUI PID 강제 종료를 확인했다.
- 단일 EXE 빌드 명령·구형 파일 제거 경계·정확히 한 개의 EXE만 허용하는 배포본 검증 **38개**를 확인했다. 위 관련 검증과 중복되는 별도 실행 결과다.
- `5d396f331b67d5a09990d5a16f6c45a08d1edc37` 소스로 실제 `강써치.exe` 한 개를 빌드하고 Windows 네이티브·배포본 **29항목 모두 통과**를 확인했다. 서버 자동 시작/정상 종료, 같은 포트 재실행, 외부 서버 생존, 명시 DB/다른 서비스 거부, 중복 창, 실제 GUI 강제 종료 후 서버 해제와 DB 무결성까지 포함한다.
- 실행 파일은 `frozen:true`, Qt 플랫폼 `windows`, 창 전용 PE 형식으로 확인했다. 읽기 진단은 PDF·DOCX 저장 본문과 기존 403·설정 복원을 함께 확인한다. 검증 도구의 SQLite 무결성 조회 연결도 명시적으로 닫아 임시 자료 정리까지 확인했다.
- Ruff·공백·문서 링크·14개 Phase 체크 개수 일치를 확인한다. Phase 14는 **1/28**로 유지한다.
- 최종 Windows Python 3.11·3.12 전체 검사, 실제 단일 EXE·배포본 결과 및 `client_dev` 반영 SHA는 이 작업 PR의 GitHub 검사·병합 기록을 따른다.
