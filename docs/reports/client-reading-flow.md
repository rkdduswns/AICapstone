# Client 상태 안내·본문 찾기·출처 메뉴·읽기 정리

작업일: 2026-11-14 (KST). 기준: `client_dev 7972188`, 확인한 `main 7e0991e`.
작업 브랜치: `feat/client-reading-flow`.

## 목적·선행조건

현재 연결된 최근 기록과 저장 본문을 읽고 원래 출처를 확인하는 흐름을 정리한다.
기존 Client 상태 처리·최근 20건 목록/날짜별 보기·실제 작업 ID·본문 조회·문서 가져오기와
개인정보 설정 화면을 선행조건으로 삼는다.

## 순서와 범위

1. 기존 오류·빈 결과 처리를 보존하면서 다음 행동 안내를 일관되게 표시한다.
   연결 대기, 선택/출처 없음, 저장 본문 없음, 현재 목록의 필터 결과 없음, 조회 실패를 구분한다.
   403을 성공이나 자동 재시도 대상으로 처리하지 않는다. 업로드 응답이 불명확하면 목록 확인을 먼저 안내한다.
2. 현재 받은 읽기 전용 본문에서만 `Ctrl+F`로 일반 텍스트를 찾는다.
   이전/다음·일치 개수·검색창 닫기를 제공하며 네트워크 검색과 구분한다.
   원문·수집 자료·검색어를 새로 저장하지 않는다. 가상 답변의 인용 강조와는 별개다.
3. 실제 선택한 기록/문서의 확인된 원본 출처에 복사·명시적 열기 메뉴를 제공한다.
   URL은 HTTP(S)만, 파일 열기는 검증된 로컬 PDF/DOCX 원본만 다룬다.
   출처 선택 변경·목록 조회 실패·재연결에서 이전 동작 대상을 비운다. 서버 사본 경로를 원본으로 추정하지 않는다.
   본문만 조회에 실패한 경우에는 현재 목록이 확인한 같은 기록의 출처를 유지할 수 있다.
   공유 경로는 복사만 지원하며 메뉴 표시나 선택 변경 자체로 파일 시스템을 조회하지 않는다.
4. 웹·문서·클립보드 본문의 여백·행간과 목록/날짜별 보기 스타일을 맞춘다.
   본문을 HTML로 처리하거나 원문과 인용 위치를 바꾸지 않는다.

Backend·DB·Shared·브라우저 확장·API·보호 판정·의존성은 변경하지 않는다.
실제 검색/RAG·전체 세션·전체 이력·삭제·자동 수집·URL 차단 서버 구현은 이번 범위가 아니다.
메모·중요도·민감 본문 저장 동의·트레이·전역 단축키도 추가하지 않는다.

## 검증·완료조건

- 상태 전환: 선택/출처 없음·정상 빈 응답·필터 0건·실패·복구에서 안내와 동작 대상을 구분한다.
- 본문 찾기: 한글/이모지·일치 없음·반복 이동·본문 교체·키보드·원문 불변 및 네트워크 요청 없음.
- 출처 메뉴: 실제 선택과 대상 일치, 선택 해제/실패 후 이전 대상 사용 불가, 잘못된 URL/경로·없는 파일·열기 실패 안내.
- 읽기/통합: 기존 실제 Backend HTTP·403·출처 검증·선택/스크롤·작은 화면·배율 회귀와 새 Windows 배포본 실행.

완료조건은 현재 Client 범위의 위 동작 검증 통과다.

- 신규 검증은 상태 안내 9개·본문 찾기 9개·출처 메뉴 34개·화면 연결 8개다.
- Windows Python 3.14.7·Qt 오프스크린·맑은 고딕 10pt에서 신규 60개와 기존 관리·최근 기록·문서·실행 편의의 관련 회귀 **114개 통과**를 확인했다.
- Qt 150% 배율에서 신규 60개와 작은 관리/출처 화면 검증 **62개 통과**를 확인했다. 물리 화면의 크기에 의존하는 전체 창 크기 복원 검증은 표준 배율 검사에서 확인했다.
- 가상 자료 PNG로 현재 본문 찾기·필터 결과 없음 안내와 실제 선택 해제 후 출처 메뉴 비활성화를 확인했다.
- 긴 문서에서 짧은 문서로 이동할 때 이전 일부 표시 안내가 남던 문제도 수정했다.
- Ruff·공백 검사 및 문서 링크·14개 Phase 체크 개수 일치를 확인한다. 실제 검색/RAG의 출처 이동과 오류 처리는 잔여이며 Phase 14는 **1/28**로 유지한다.
- 최종 Windows Python 3.11·3.12 전체 검사, 새 EXE 실행 결과 및 실제 `client_dev` 반영 SHA는 이 작업 PR의 GitHub 검사·병합 기록을 따른다.
