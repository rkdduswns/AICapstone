## 1. 코드가 해결하는 문제

연결 확인·현재 작업·최근 기록을 화면에 표시하고, 사용자 조작과 통신 객체의 신호를 연결합니다. 실제 수집·저장·시간 계산을 UI에 넣지 않습니다.

## 2. 먼저 알아야 할 개념

- QWidget은 화면 구성의 기반이고 레이아웃은 자식 위젯의 배치를 관리합니다.
- `connect(self.check)`는 나중에 호출할 함수를 등록합니다. `connect(self.check())`와 다릅니다.
- Signal은 C# 이벤트와 목적을 비교할 수 있지만, 신호를 연결했다는 사실만으로 스레드가 만들어지지는 않습니다.
- `self`에 담은 위젯/클라이언트는 나중의 이벤트 처리기에서도 접근합니다.
- 사용자용 결과 문구와 로직용 bool 상태는 별도 신호로 전달합니다.

## 3. 전체 실행 순서

1. `__init__`이 라벨·버튼·탭·클라이언트를 만들고 신호를 연결합니다.
2. 버튼 클릭으로 `check()`가 호출됩니다. 기존 조회 중단, 이전 표시 제거, 버튼 비활성화 후 요청합니다.
3. BackendClient의 `result` 신호가 `_show_result()`를 호출해 문구와 확인 시각, 버튼을 갱신합니다.
4. `connection_changed`가 `_connection_changed()`를 호출합니다. 성공이면 현재 작업 조회를 시작합니다.
5. 검증된 스냅샷이 오면 `_show_activity()`가 표시합니다. 실패/창 없음이면 `_clear_activity()`로 비웁니다.
6. 최근 기록 탭 선택 시 `_tab_changed()`가 최근 기록 위젯의 조회를 요청합니다.
7. 창을 닫으면 `closeEvent()`에서 타이머·진행 중 요청을 정리합니다.

## 4. 함수별 / 코드 블록별 설명

| 함수 | 역할 | 알아둘 상태 변화 |
|---|---|---|
| `display_label` | 일반 텍스트용 라벨 생성 | 외부 데이터를 HTML로 해석하지 않습니다. |
| `__init__` | 위젯/통신 객체/신호 연결 구성 | 아직 연결 확인 요청은 보내지 않습니다. |
| `check` | 연결 재확인 시작 | 중복 방지·이전 조회 취소·버튼 잠금. |
| `_show_result` | 마지막 연결 결과 표시 | 버튼을 다시 활성화하고 확인 시각을 갱신합니다. |
| `_connection_changed` | 성공 여부에 따른 조회 제어 | 성공 시 자동 조회를 시작합니다. |
| `_show_activity` | 스냅샷 표시 | 제목이 같으면 불필요하게 다시 쓰지 않습니다. |
| `_clear_activity` | 이전 감지값 제거 | 마지막 정상 수신 시각은 과거 이력으로 남깁니다. |
| `_now` | 확인/수신 시각의 표시 문자열 | 작업 시작 시각이나 누적 시간 계산은 아닙니다. |
| `closeEvent` | 화면 종료 시 요청 정리 | 늦은 응답이 닫힌 화면을 갱신하지 않게 합니다. |

## 5. 하나의 예시를 끝까지 따라가기

Backend가 꺼져 있을 때 연결 확인을 누른다고 가정합니다.

1. `status`는 `연결 중`, 버튼은 비활성화됩니다.
2. BackendClient가 연결 오류 또는 timeout을 전달합니다.
3. `_show_result()`가 오류 문구·확인 시각을 쓰고 버튼을 다시 켭니다.
4. `_connection_changed(False)`가 창/시간 표시를 비웁니다.
5. Backend를 실행한 후 재확인하면 새 결과에 따라 조회를 시작할 수 있습니다.

Phase 1 Backend에만 연결했을 때는 health 성공 뒤 현재 창 API가 404여서 `기능 준비 중`이 될 수 있습니다. 서버 연결과 기능 준비 상태는 다릅니다.

## 6. 실패 및 경계 상황

- 통신 실패 시 과거 제목을 현재 감지 결과처럼 남기지 않습니다.
- 시간 정보가 없으면 `시간 정보 없음`이며 0초로 채우지 않습니다.
- 시작 시각, 누적 활성 시간, 마지막 정상 수신 시각의 의미가 서로 다릅니다.
- `_show_activity()`는 입력 모델이 검증되었다고 가정합니다. 원시 JSON 검증 책임을 UI로 옮기지 않습니다.
- 탭 위젯·ActivityClient·시간 표시 함수의 내부 구현은 이 사본에 포함되지 않았습니다. 원본 import를 따라 읽습니다.

## 7. 이해 확인과 작은 실습

1. 문구를 바꾸더라도 연결 판단이 유지되는 이유를 두 신호의 차이로 설명합니다.
2. 동일 제목을 반복 setPlainText하지 않는 이유를 적습니다.
3. 요청 중 창 닫기에서 어떤 객체를 어떤 순서로 정리하는지 찾습니다.
4. 이해 기준: 메서드 선언 순서가 아닌 버튼/응답/탭/종료 이벤트 순서로 코드를 설명할 수 있습니다.
