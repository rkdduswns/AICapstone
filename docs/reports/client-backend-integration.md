## 주요 변경

- Client가 새 Backend의 `paused`·`blocked` 상태를 계약 오류로 처리하던 문제를 수정했다.
- 추적·업로드·설정·클립보드가 같은 정책과 지연 생성 저장소를 사용한다. 주입한 DB도 모든 경로에 적용된다.
- 수집은 서버 lifespan에서 1초 간격으로 실행하여 Client 탭/연결에 의존하지 않는다. 정상 종료 시 마지막 세션을 저장한다.
- 설정 PUT은 명시적 목표값을 적용한다. JSON/전용 헤더를 확인하고 웹 Origin 요청과 다른 필드가 섞인 본문을 거부한다.
- 정책 변경 경계에서 허용된 이전 세션을 닫고, 이후 수집과 문서/브라우저 수신에도 변경된 일시정지를 적용한다.
- Windows 클립보드는 변경 번호와 소유 프로세스를 확인한다. 켜기/재개 전 내용, 다른 프로세스의 내용, 읽는 중 변경된 내용은 현재 작업에 연결하지 않는다.
- 민감 패턴이 있는 클립보드·브라우저 본문·문서 본문은 저장하지 않는다. 클립보드는 10,000자를 초과하면 저장하지 않는다.
- 기존 클립보드 스키마는 작업 FK 대신 애플리케이션·세션 시작 시각을 사용한다. 같은 키의 작업이 여러 개면 연결을 추측하지 않고 빈 결과를 반환한다.
- 문서 가져오기는 20 MiB까지 지원하고 업로드를 자동 재전송하지 않는다. 통신 결과가 불명확하면 목록 확인을 안내한다.
- 연결 없는 문서는 파일 이름·가져온 시각을 표시한다. 명시적으로 연결한 문서는 실제 선택 경로·작업 번호도 표시한다. 가져온 시각과 원래 작업 시각은 별도이며 본문은 일반 텍스트로 최대 50,000자까지 표시한다.

## 2026-10-22 이력 연결

- 진행 중 세션의 최초 샘플에 실제 SQLite ID를 발급한다. 이후 샘플/종료는 같은 행을 갱신하고 현재 작업 응답의 선택적 `record_id`로 전달한다.
- 기존 DB를 보존하는 두 FK 연결 테이블을 추가했다. 출처와 연결을 같은 트랜잭션에 쓰며 기존 자료를 제목/시각 근접도로 추측해 연결하지 않는다.
- 브라우저는 Bearer 인증 뒤 현재 작업 ID·프로세스를 재확인한다. 같은 제목의 다른 정제 URL은 세션을 나누고 이전 페이지를 보존한다. 같은 출처 재전송은 행을 재사용하며 늦게 도착한 이전 작업의 본문은 거부한다.
- 수동 Chrome/Edge 확장은 활성 탭 확인→현재 작업 확인→DOM 스냅샷→탭 이동 재확인→출처/본문 전송 순서다. 일시정지/다른 프로세스는 DOM 읽기 전에 중단하고 고정 loopback 외에는 요청하지 않는다.
- 문서는 최근 기록의 선택 대상을 명시해 업로드한다. Windows 절대 경로·파일 이름·desktop 요청·작업 존재를 검사하며 경로로 파일을 다시 열지 않는다. 실제 업로드 바이트를 추출한다.
- 최근 기록은 최신 실제 연결 출처만 투영한다. 기존 웹/문서 상세 조회 계약으로 저장 본문·출처·수집 시각을 제공하고 50,000자 초과를 명시한다.
- 설치·실행·API·제한은 [이력 연결 안내](../dev/history-source-linking.md)에 기록했다. 이 브랜치와 Draft PR #16은 main 미병합 상태다.

## 검증

- 변경 전 main: Linux 전체 479개 테스트 통과.
- 실제 Uvicorn loopback 서버에 QtNetwork Client를 연결했다. 감지기·시계·클립보드 원문만 가상 데이터를 주입하고 API/추적기/SQLite/문서 추출은 실제 구현을 사용했다.
- 일시정지·재개·차단 입력, 세션 저장과 최근 조회, 작업별 복사 원문, 실제 DOCX multipart 업로드와 목록/본문, 일시정지 중 업로드 거부를 검증했다.
- 별도 Backend 인스턴스의 기존 DB 재조회, 잘못된 설정 거부, 세션 키 충돌, 민감·과도한 클립보드, 변경 번호·소유 프로세스 검사도 확인했다.
- 2026-10-21 부분 통합: Linux 전체 **504 passed**. Windows Python 3.11·3.12도 **503 passed, 1 skipped**(POSIX DST 전용)로 통과했다.
- 2026-10-22 이력 연결: Linux / Python 3.12.14 / PySide6·Qt 6.12.0 전체 **529 passed** (122.60초), 이번 신규 25개. 기존 Starlette/httpx 경고 1건.
- 실제 Uvicorn·Qt 화면에서 작업 선택→문서 업로드→최근 기록 자동 갱신→문서 본문 표시와 브라우저 수신→최근 웹 본문 표시를 검증했다. OS 감지·시계·Windows 선택 경로는 가상 입력이며 추출·HTTP·SQLite는 실제 구현이다.
- 같은 제목의 URL 변경, 잘못된 작업/프로세스/토큰, 일시정지, 늦은 본문, 경로 오류, 웹 Origin 요청, 추출 중 대상 삭제의 롤백, 구형 DB 보존·재조회·긴 본문을 검증했다.
- Node 확장 경계 테스트 **8 passed**. Chrome API·HTTP를 주입해 중단 순서·포트·프로세스·탭 변경·내부 페이지·인증 오류·전송 ID를 검사한다. 설치한 Chrome/Edge 수동 검증과 구분한다.
- Ruff, `uv pip check`(34개 패키지), diff 검사, 14개 Phase의 개수·항목 상태와 로컬 문서 링크 대조 통과.
- Linux offscreen에서 620×740 문서 탭의 한글·버튼·연결 대상·작업 번호·경로·본문 배치를 확인했다. Windows 수동 검증을 대체하지 않는다.
- Windows Python 3.11·3.12 자동 검증 결과는 이 브랜치의 main 대상 PR checks를 따른다.

## 남은 검증과 기능

- 실제 Windows 데스크톱에서 창 전환·복사·배율/한글 표시를 수동 검증해야 한다. 가상 감지기와 CI 실행만으로 전체 Phase를 완료 처리하지 않는다.
- 재방문 집계는 아직 없고 `foreground_count`는 세션별 1이다. 강제 종료 전 마지막 저장 샘플 이후 구간은 복구하지 않는다.
- 설정은 Backend 프로세스 메모리에서 관리한다. 재실행 시 수집 허용·클립보드 꺼짐·빈 차단 목록으로 초기화된다.
- 클립보드는 폴링 사이 여러 번의 복사를 모두 보존하지 않으며 수집 시각을 기록한다. 소유 프로세스를 확인할 수 없는 복사는 저장하지 않는다.
- Browser 확장은 사용자 버튼으로만 캡처한다. 자동 탭 이벤트·SPA 전환·본문 정제·URL 차단은 후속 작업이다. URL query/fragment는 기존 Backend 정책상 저장하지 않는다.
- 문서 연결은 사용자가 선택한 작업과 파일의 명시적 연관이다. 자동 열린 파일 식별이나 원래 열람 사실의 자동 증명을 의미하지 않으며 중복 업로드를 합치지 않는다.
- 자동 PDF/DOCX 감지, 검색·임베딩·LLM은 이번 통합 범위에 포함하지 않는다.
