# 시스템 아키텍처

ContextTrace는 크게 **수집 계층, 개인정보 보호 계층, 전처리 계층, 저장 계층, 검색 계층, RAG 계층, 사용자 인터페이스 계층**으로 구성합니다.

---

## 1. 수집 계층

Windows에서 현재 사용자가 보고 있는 작업 대상을 감지합니다.

주요 구성 요소:

- 활성 창 감지
- 프로세스 확인
- 창 제목 추출
- 브라우저 URL 수집
- 로컬 파일 정보 수집
- 클립보드 변화 감지

수집 계층은 애플리케이션별 차이를 흡수하기 위해 어댑터 구조를 사용합니다.

---

## 2. 개인정보 보호 계층

수집된 정보를 데이터베이스로 보내기 전에 저장 가능 여부를 판단합니다.

```text
수집된 작업 정보
      ↓
프로그램 차단 여부 확인
      ↓
URL 차단 여부 확인
      ↓
민감 정보 탐지
      ↓
저장 또는 폐기
```

이 계층은 데이터 저장 이후가 아니라 **저장 이전에 적용**하는 것을 원칙으로 합니다.

---

## 3. 전처리 계층

반복적으로 생성되는 작업 기록을 검색 가능한 형태로 가공합니다.

주요 처리:

- 중복 작업 로그 병합
- 불필요한 텍스트 제거
- PDF / DOCX 텍스트 추출
- 긴 문서 분할
- 작업 세션 생성
- 임베딩 생성

---

## 4. 저장 계층

정형 데이터와 의미 검색용 데이터를 분리합니다.

### SQLite

저장 대상:

```text
시간
프로그램
프로세스
창 제목
URL
파일 경로
활성 시간
세션 ID
```

### 벡터 데이터베이스

저장 대상:

```text
문서 조각
텍스트 임베딩
원본 작업 기록 ID
검색용 메타데이터
```

---

## 5. 검색 계층

사용자 질의를 분석하여 필요한 검색 방식을 조합합니다.

예:

> 어제 오후에 PDF로 봤던 AI Agent 관련 자료 찾아줘.

분석 결과:

```text
어제 오후
→ 시간 범위

PDF
→ 파일 형식

AI Agent
→ 의미 검색어
```

검색 순서:

```text
질의 분석
      ↓
SQLite 조건 검색
      ↓
검색 후보 축소
      ↓
벡터 검색
      ↓
결과 재정렬
```

---

## 6. RAG 계층

검색된 자료를 LLM에 제공하고 사용자가 이해하기 쉬운 형태로 정리합니다.

중요한 점은 **LLM 자체의 일반 지식보다 검색된 기록을 우선 근거로 사용하도록 제한하는 것**입니다.

출력 예:

```text
답변
출처 문서명
URL 또는 파일 경로
열람 시간
관련 작업 세션
```

---

## 7. 사용자 인터페이스 계층

초기 버전은 Windows 데스크톱 애플리케이션 형태로 구성합니다.

주요 화면:

```text
검색 화면
검색 결과
출처 상세보기
작업 타임라인
기록 일시정지
개인정보 설정
```

Python 백엔드와의 통합을 고려하여 초기 UI는 PySide6 사용을 우선 검토합니다.
