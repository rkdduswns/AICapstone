# 개인정보 보호 설계

ContextTrace는 OS 수준의 작업 정보를 수집하기 때문에 개인정보 보호 기능을 핵심 기능으로 포함합니다.

기본 원칙은 **민감한 데이터를 저장한 뒤 처리하는 것이 아니라, 저장 전에 차단하는 것**입니다.

---

## 개인정보 처리 흐름

```text
수집된 작업 정보
      ↓
프로그램 차단 목록 확인
      ↓
URL 차단 목록 확인
      ↓
민감 텍스트 탐지
      ↓
저장 허용 여부 결정
      ↓
로컬 저장
```

---

## 1. 프로그램 차단 목록

사용자가 지정한 프로그램이 활성화된 경우 작업 기록을 저장하지 않습니다.

예:

```text
비밀번호 관리자
메신저
은행 프로그램
사내 보안 프로그램
사용자가 직접 지정한 프로그램
```

설정 예:

```json
{
  "blocked_apps": [
    "KeePass.exe",
    "KakaoTalk.exe"
  ]
}
```

---

## 2. URL 차단 목록

특정 사이트가 활성화되어 있을 경우 URL과 페이지 정보를 저장하지 않습니다.

예:

```text
bank.example.com
mail.example.com
company.internal
```

지원 방식:

```text
정확한 주소 일치
도메인 단위 차단
와일드카드 기반 차단
```

---

## 3. 민감 텍스트 탐지

클립보드나 문서에서 민감한 정보가 발견되면 저장하지 않거나 일부를 마스킹합니다.

탐지 대상 예:

- 비밀번호 형태
- OTP
- API Key
- Access Token
- 카드 번호
- 주민등록번호 형태
- 기타 사용자가 지정한 문자열 패턴

초기 구현에서는 정규표현식 기반 필터를 사용합니다.

```text
수집 텍스트
      ↓
민감 패턴 탐지
      ↓
민감함
  ├─ 예 → 저장하지 않음
  └─ 아니오 → 저장
```

---

## 4. 기록 일시정지

사용자는 언제든 전체 로그 수집을 일시정지할 수 있어야 합니다.

```text
[ 기록 중 ]

기록 일시정지
기록 재개
```

Windows 시스템 트레이 아이콘을 통해 즉시 제어할 수 있도록 구성할 수 있습니다.

---

## 5. 로컬 우선 저장

작업 로그와 원본 메타데이터는 기본적으로 사용자 PC에 저장합니다.

```text
SQLite
벡터 데이터베이스
문서 색인
작업 로그
```

로컬 저장은 데이터 통제권을 사용자에게 제공하기 위한 방식이며, 단순히 로컬이라는 이유만으로 안전하다고 가정하지 않습니다.

추가 고려사항:

- 데이터베이스 파일 접근 권한 제한
- 로컬 암호화
- 사용자가 직접 로그 삭제 가능
- 보존 기간 설정
- 전체 기록 삭제 기능

---

## 6. 외부 LLM API 사용 시 처리

외부 LLM API를 사용하는 경우 검색된 문서 내용 일부가 외부 서비스로 전송될 수 있습니다.

따라서 두 가지 실행 방식을 고려합니다.

### 로컬 우선 모드

```text
로컬 임베딩
+
로컬 검색
+
로컬 LLM
```

### 외부 LLM 사용 모드

```text
로컬 검색
      ↓
필요한 검색 결과만 선택
      ↓
민감 정보 마스킹
      ↓
LLM API 호출
```

외부 API에 전체 작업 기록이나 원본 데이터베이스를 전송하지 않는 것을 원칙으로 합니다.

---

## 7. 개인정보 설정 화면

사용자가 직접 다음 항목을 관리할 수 있도록 합니다.

```text
차단 프로그램 목록
차단 URL 목록
민감 문자열 패턴
기록 일시정지
로그 삭제
데이터 보존 기간
외부 LLM 사용 여부
```
