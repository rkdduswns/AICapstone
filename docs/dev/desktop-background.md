# Windows 백그라운드 실행과 출처 연결

Phase 14 후속 작업. 폴더 정리 브랜치 위에서 기존 두 EXE 배포 형식을 유지한다.
Windows에서 Client를 실행하면 같은 사용자·포트의 창을 하나만 사용한다. 시작 중인 창도 잠금을 보유한다.
호환되는 외부 Backend는 재사용하고 앱이 띄운 Backend만 종료한다. 외부 서비스가 포트를 점유하면 해당 서비스를 중단하지 않는다.
따로 실행한 Backend도 DB를 열기 전에 포트를 확보한다. Windows 시작 시 자동 실행되는 서비스 설치는 하지 않는다.

- **닫기와 종료:** 일반 창의 X는 트레이로 숨긴다. 질문은 계속 처리되며 완료·실패 시 내용 없는 알림을 표시한다. 트레이·알림·재실행은 기존 창을 연다. 작업 표시줄 트레이가 없으면 질문 대기 중에는 최소화하고 결과가 오면 창을 복원한다. 명시적 종료 후 요청을 재개하거나 답변을 디스크에 보관하지 않는다.
- **감지 범위:** 강써치 EXE와 Windows에서 표시한 자기 창·소유 대화상자는 제목을 읽기 전에 수집을 중단한다. 다른 Python 앱은 계속 감지 대상이다.
- **창과 본문:** 검색창은 최대화 버튼 없이 검색 결과·상세 영역을 펼친다. 문서 본문은 읽기 전용 별도 창에서 최대화할 수 있다. 파일 형식에 연결된 외부 앱을 자동 실행하지 않는다.
- **웹:** ZIP 확장의 연결 설정을 저장하고 원하는 사이트에서 자동 연결을 한 번 허용한다. 해당 사이트의 활성 창·탭에서만 URL·제목을 기존 작업 ID에 연결한다. 시크릿 창 및 백그라운드 탭은 제외한다. 본문을 저장하려면 수동 연결 옵션을 연다. 소스 전용 ContextTrace는 별도 확장이다.
- **문서:** 선택해 가져온 PDF·DOCX에 대해 Word 또는 Acrobat Reader의 기록 한 건에 같은 전체 경로가 있어야 자동 연결한다. 파일명이 같거나 여러 작업이 같은 문서를 가리키면 문서만 가져온다. 직접 지정하려면 최근 기록의 **출처 연결 옵션**을 사용한다. 연결한 본문은 기존 로컬 색인을 통해 검색·답변 근거로 사용한다. PC 전체 파일 검색이나 열람 파일의 무조건적인 수집은 하지 않는다.

## Windows 실사용 확인

두 EXE와 models를 같은 폴더에 놓고 Client를 두 번 실행한다. 창이 하나이고 콘솔이 뜨지 않는지 확인한다.
질문 후 X를 누르고 응답 알림을 클릭한다. 같은 답변이 보이며 최근 작업에 강써치 제목이 없어야 한다.
트레이에서 종료한 뒤 같은 포트로 재실행한다. Chrome에서는 허용·미허용 사이트를 번갈아 열어 출처가 허용한 쪽에만 생기는지 확인한다.
